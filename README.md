# Jobin · React Native for iOS, Android and web

One Expo SDK 54 / React Native 0.81 app, with Expo Router navigation and React Native Web. This replaces the previous Next.js frontend. All screens use React Native primitives and shared state; no browser-only DOM or CSS.

## Run
Node.js 22.13+ and npm:

```sh
npm install
npm start
```

- `npm run ios`: launch the iOS simulator (macOS with Xcode required).
- `npm run android`: launch an Android emulator (Android Studio required).
- `npm run web`: launch the web app.
- Physical devices: use a compatible SDK 54 Expo Go build, or create a development build. The current store version of Expo Go may no longer support SDK 54.

## Checks
```sh
npx expo install --check
npm run lint
npm run typecheck
npm test
npm run export
```

The GitHub Actions workflow runs these checks and exports JavaScript/assets for iOS, Android and web. Exporting native bundles does not compile, sign or test native binaries. The first install generates a lockfile; commit that file after dependency validation to make subsequent installs reproducible.

## Build / distribution
```sh
npx eas-cli@latest build --platform android --profile preview
npx eas-cli@latest build --platform ios --profile preview
npx eas-cli@latest build --platform all --profile production
npm run export:web
```

Preview produces an Android APK and an iOS simulator build. Physical iOS distribution needs an appropriate EAS profile and Apple provisioning. Production builds need your Expo project configured and Apple/Google developer accounts. Confirm the configured bundle/package IDs before publishing. Serve `dist/` for web; choose a host that resolves exported route HTML. Do not deploy with the old Next.js settings.

Native projects are generated by Expo; configure via app.json rather than editing ios/ or android/.

## Features
- Responsive visual discovery feed with virtualized cards and city filters.
- Save/like professionals; service navigation with selected professional.
- Services and pricing with explicit demo-only booking notices.
- Professional, friendship and dating modes, swipe gestures, accessible skip/interest buttons.
- Independent interests per mode, duplicate prevention, and no fabricated mutual matches.
- Local communities; profile with optional relationship status.
- Shared session state survives tab changes; resetting the app or browser clears it.

## Integration status
All people, services and community counts are sample data. There is no authentication, durable persistence, actual video, upload, booking, payment, chat, calendar or video calling yet. Backend work is tracked in docs/roadmap.md. Private provider keys must stay on a server, never in EXPO_PUBLIC_ variables.

## Structure
- src/app: Expo Router screens and tab layout.
- src/components: shared React Native UI and swipe deck.
- src/state: session provider.
- src/lib: demo data and pure connection/filter helpers.
- tests: domain behavior checks.

## Manual platform smoke test
On iOS, Android and web: change city; save a card; navigate to its service; try its demo availability action; return to the feed; swipe/skip in each connection mode; verify that no unilateral interest appears as a match; join/leave a community; edit name and relationship status; rotate the screen and use a narrow browser viewport. Verify keyboard, safe areas, screen-reader labels and browser back navigation.
