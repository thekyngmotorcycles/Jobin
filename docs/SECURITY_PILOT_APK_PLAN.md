# Jobeen — variante Android aislada (no compilar sin aprobación)

Estado: preparación de código, CI pendiente, NO lista para EAS ni pruebas de autenticación. Norma AGENTS.md y SEC-05.

- Perfil de EAS: `security-pilot`, sólo por invocación manual autorizada. Usa app.config.js con marca `JOBEEN_SECURITY_PILOT=1` y `EXPO_PUBLIC_JOBEEN_SECURITY_PILOT=1`. No ejecutar EAS desde este cambio.
- Android package `com.thekyngmotorcycles.jobin.securitypilot`, separado de la instalación actual. Scheme `jobeen-security-pilot` para OAuth, sin reutilizar `jobin://`. `updates.enabled=false` (no OTA en el piloto); identidad y almacenes Android distintos.
- Backend: requiere un proyecto Supabase de pruebas independiente con credenciales publicables independientes `EXPO_PUBLIC_SUPABASE_URL` y `EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY` disponibles para EAS en su entorno `development`. El constructor rechaza falta de valores, URL real conocida, URI no HTTPS o token no publicable. El cliente del piloto también deniega fallback al backend normal. No imprimir claves ni invocarlas en logs. No existe todavía aprobación para crear ni aplicar un entorno alojado.
- OAuth: `jobeen-security-pilot://` debe añadirse sólo a la lista permitida en el proyecto aislado con proveedor Google y callback HTTPS propios; sin esa configuración, no declarar Google probado. La reautenticación, recuperación, Storage y RLS deben probarse con usuarios ficticios del proyecto de pruebas. No asumir que export o CI confirman funcionalidad real.
- `src/lib/backend-config.ts` normal se mantiene intacto y la aplicación normal conserva scheme/package/OTA anteriores. Los flags se evalúan en Expo config y JS; confirmar en el artefacto binario y no exponer la instalación existente.
- Incluir SecureStore, módulos de cámara/micrófono, reproducción, selector, GPS/Mapbox, contactos, notificaciones y módulo Android JobeenPrivateFiles existente. Autolinking sólo verifica presencia en configuración; falta Gradle, KeyStore y pruebas nativas. El controlador de transferencia de video y el cifrado de fotos requieren integración real (SEC-02/03), no declarar listos por estar incluidos en APK.
- Gate: CI verde y `expo config --type public` con valores sintéticos aislados + revisión sin compilar; configuración propia de EAS/Expo y firma de piloto revisadas; aprobación explícita del propietario para el SHA exacto ANTES de cualquier EAS Build; ejecutar y probar sólo sobre datos ficticios en dispositivo. No distribuir como actualización de la aplicación actual.
- Pendientes para una APK verdaderamente consolidada de funciones futuras: RTC de directos/entrevistas y facturación no tienen todavía SDK seleccionado; no añadir ambos sólo para evitar otra APK hasta que proveedor, integración y controles de permisos estén decididos. Si el objetivo inmediato es seguridad nativa, la APK de piloto puede probar módulos existentes sin habilitar flujos multimedia incompletos.
