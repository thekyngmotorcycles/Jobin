## 2. Candidatos concretos para el siguiente lote
A. LiveKit: documentación Expo oficial indica @livekit/react-native, @livekit/react-native-webrtc, @livekit/react-native-expo-plugin, @config-plugins/react-native-webrtc y livekit-client; dos config plugins y registerGlobals; tokens de servidor, sin cámara/micrófono activados automáticamente. Resolver versiones/peers en npm real con Expo 54/RN 0.81.5, React 19.1 y New Architecture. No usar latest sin comprobación. No afirmar compatibilidad hasta npm ci/expo check y pruebas de integración. livekit-server-sdk es backend, no app.
B. expo-audio: seleccionar versión compatible usando npx expo install expo-audio sobre SDK 54, no la última versión global. Confirmar plugin/permiso de micro, audio en primer plano, coexistencia LiveKit, recuperación/cancelación, privacidad. El módulo jobeen-private-files actual cifra objetos y lee archivos seleccionados; NO asumir que protege automáticamente todos los archivos temporales de un grabador, implementar consumo seguro y limpieza antes de habilitar dictado real. Reutilizar el módulo; si una extensión nativa es indispensable, incluirla en el mismo lote tras pruebas.
C. IAP: selección técnica recomendada expo-iap (una sola biblioteca, no RevenueCat ni IAPKit), con versión compatible pendiente de resolución y autorización del lote. JShop y JQuote físico usarán checkout alojado externo, sin SDK adicional, según docs/JOBEEN_PAYMENTS_PLAN.md. Si ambas incompatibles con SDK54 o el negocio no ha decidido, autorización del propietario para excluir y plan de compilación de monetización, sin retrasar indefinidamente Streaming. No comprar nada ni conectar credenciales. Verificar políticas vigentes de cada tienda antes de ofrecer compra. El backend valida transacciones y permisos; no guardar secretos en cliente.
D. Ya presentes: comprobar expo-file-system 19.0.24 y expo-keep-awake 15.0.8 transitivos del Expo del lock anterior. No duplicar versiones: si se requieren APIs directas, declarar versión compatible y verificar resolución, autolinking y fingerprint. No asumir que importación directa funciona por dependencia transitiva. No ampliar permisos de almacenamiento general.
E. Comprobar la cobertura de todos los módulos locales y plugins del lote, incluida configuración de notificaciones push, AudioSession, orientation/foreground y memoria/disco de Jelly. No incluir fondo/screen sharing/PiP si no se aprueban. No agregar SDK de pagos físicos ni IA local.
