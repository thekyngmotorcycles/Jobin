# SEC-03 · Transferencia privada de video

Rama `feat/sec03-private-video-integration`, basada en el HEAD remoto `6fc433f386a5e7801d322159fc8137874403a55c` de `fix/message-jshop-authorization-20261121`. La integración profesional se verificó en aislamiento. Su activación permanece bloqueada hasta validar el entorno y el dispositivo. Flash sigue como borrador local con su interfaz aprobada.

## Integración y verificación

- El editor profesional usa el controlador existente. Solo permite iniciar la transferencia con una selección del usuario en la sesión activa. Un borrador reabierto conserva su metadato pero requiere volver a seleccionar el video para enviarlo. La ruta de subida anterior de `safety-api.ts` quedó sin consumidores. Su retirada queda para la integración coordinada porque el archivo incluye el flujo de evidencias reservado a SEC-02.
- Android reutiliza el módulo FileSystem de Expo SDK 54 si el binario incluye lectura acotada. Abre un *handle* de caché local por segmento y comprueba tamaño, modificación y cierre. Web usa `Blob.slice` del archivo que entrega el selector. Las URI sin archivo verificable se bloquean. No hay una cola persistente ni un nuevo SDK.
- TUS usa 6 MiB por segmento, un último tramo menor y un máximo de 500 MiB. Tras un fallo, el usuario puede reintentar con la misma selección y los mismos datos en primer plano. El cliente consulta el offset confirmado y la finalización reutiliza el recibo de moderación. Salir del editor o pasar a segundo plano aborta la petición local y pide cancelar el ticket cuando la sesión permite hacerlo.
- El gateway candidato verifica las credenciales con GoTrue y vuelve a consultar la sesión activa, sanciones, propietario y ticket en Postgres. La ubicación TUS del origen queda solo en servidor. Las ACL candidatas cierran lectura, firma y escrituras directas para los usuarios del bucket de originales. La confirmación exige tamaño y tipo del objeto guardado y usa la RPC de moderación existente en la misma transacción que el recibo idempotente. Las bajas de sesión impiden nuevas operaciones. Una petición ya admitida puede dejar bytes en cuarentena sin confirmar.
- El ensayo usó GoTrue 2.188.1, PostgREST 14.8, PostgreSQL 17 y Storage 1.48.28 locales. Verificó una subida en dos segmentos con JWT reales, aislamiento entre cuentas y entre dos sesiones de A, revocación, cancelación y denegación de la ruta Storage y RPC heredadas. Las pruebas HTTP sintéticas verificaron pérdida de respuesta tras persistir un bloque y tras confirmar, reintentos, redirección rechazada y fuentes nativas simuladas. [Supabase TUS](https://supabase.com/docs/guides/storage/uploads/resumable-uploads)
- En esta rama pasaron las 15 pruebas seleccionadas, TypeScript y la exportación JS para Android. Lint terminó con cero errores y 79 advertencias existentes. La corrida de GitHub Actions para el commit base aprobó `validate` y `database`. [CI del commit base](https://github.com/thekyngmotorcycles/Jobin/actions/runs/45046854835)

## Activación y pendientes de integración

1. **SEC-05 y SEC-06.** Preparar el backend aislado y montar el gateway en un origen HTTPS de prueba con el SQL candidato. Mantener privado el origen TUS y su ubicación interna. La app solo activa el transporte con `EXPO_PUBLIC_JOBEEN_SECURITY_PILOT=1` y `EXPO_PUBLIC_PRIVATE_VIDEO_UPLOAD_URL` apuntando al origen autorizado. El gateway usa credenciales exclusivas del backend. En web, configurar CORS para el origen exacto del cliente y exponer las cabeceras de confirmación, offset y ubicación; usar rutas sin caché ni redirecciones.
2. **SEC-03.** Validar el perímetro de prueba desde fuera del origen, permisos del proveedor, límites operativos, limpieza de transferencias incompletas y conciliación de originales sin recibo. En el piloto un ticket vence tras seis horas y se admiten como máximo tres pendientes simultáneos y veinte altas por cuenta en 24 horas. La caducidad del ticket no elimina bytes en Storage. Revisar enlaces antiguos, segmentos de reproducción, origen y CDN al retirar permiso. No abrir los grants anteriores durante una reversión.
3. **SEC-07.** Confirmar en Jelly 2 que el binario incluye el FileSystem compatible. Probar selección, memoria con un video representativo, corte de red, reintento, cancelación, segundo plano y A→B→A. La revisión de código y los ensayos HTTP no acreditan comportamiento físico.
4. **Flash.** Activar la transferencia para este formato cuando exista su contrato propio de duración, moderación, publicación y autorización. El gateway actual acepta exclusivamente `work-video`.

## Reproducción

Cargar las migraciones del repositorio y `supabase/security-review/private-video-upload.sql` en PostgreSQL descartable con GoTrue, PostgREST y Storage TUS en loopback. Exponer `public` por PostgREST con los roles estándar y habilitar acceso a `service_role` solo desde el gateway.

- Pruebas TypeScript y HTTP local con `node --experimental-strip-types --test tests/private-video-integration.test.ts tests/private-video-transfer.test.ts tests/reel-draft-exit.test.ts tests/video-metadata-vault.test.ts`.
- Integración real con `node --experimental-strip-types tests/private-video-storage.local.mjs` y las variables de entorno de prueba `PILOT_AUTH`, `PILOT_REST`, `PILOT_STORAGE`, `PILOT_ANON_KEY` y `PILOT_SERVICE_KEY`. El script solo admite servicios en `127.0.0.1`.
