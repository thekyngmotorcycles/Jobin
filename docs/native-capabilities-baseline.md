# Jobeen · Inventario para la futura base nativa

Inventario de `package.json`, lockfile, árbol instalado, plugins de Expo y consumidores del repositorio. La base es Expo SDK 54, React Native 0.81.5 y New Architecture. El lockfile registra Expo 54.0.38. La presencia en el repositorio no acredita que un módulo esté incluido en la APK del Jelly 2. Este inventario no añade dependencias ni autoriza una compilación.

| Capacidad | Disponible en el repositorio | Trabajo futuro y criterio para añadir dependencias |
| --- | --- | --- |
| Almacenamiento seguro de tokens | La sesión de Supabase utiliza AsyncStorage. No está instalado `expo-secure-store`. | Evaluar SecureStore para secretos pequeños protegidos por Android Keystore e iOS Keychain. Verificar límites, restauración, reinstalación, invalidación y cierre por cuenta. Preferir una reautenticación controlada para migrar. No transferir tokens sin titularidad comprobada. |
| Cifrado de datos locales | Hay persistencia en AsyncStorage. `expo-file-system` 19.0.24 ya está instalado transitivamente a través de Expo. | Minimizar la persistencia. Validar recuperación y borrado de claves. Evitar cifrado casero, copias en claro y módulos de archivos duplicados. |
| Biometría | No está instalado `expo-local-authentication`. | Evaluar LocalAuthentication para desbloqueo local voluntario, con alternativa de acceso y pruebas de cambio de biometría y bloqueo del dispositivo. La autorización de operaciones sensibles seguirá en servidor. |

La aceptación debe cubrir Jelly 2, inicio, reapertura, cambio de cuenta, permisos denegados, revocación y recuperación de conexión.

## Clasificación para una APK consolidada

El alcance funcional se toma de la hoja de ruta actualizada, incluidos descubrimiento y oportunidades. Los cambios de producto y monetización todavía no se implementan. [Hoja de ruta aprobada](https://github.com/thekyngmotorcycles/Jobin/blob/851573f50edbea46cab8ed1695ee7f22a0027225/docs/APPROVED_PRODUCT_ROADMAP.md)

| Clasificación | Base propuesta y criterio de inclusión |
| --- | --- |
| Imprescindibles para seguridad | Un almacenamiento seguro de secretos pequeños, con SecureStore como primera opción para evaluar en SDK 54. Si el producto debe conservar datos sensibles offline, seleccionar un único componente de cifrado autenticado por archivo o registro, con claves por cuenta protegidas por el sistema. Si se puede eliminar esa persistencia y recuperar del servidor, evitar agregar un módulo de cifrado sin uso. AsyncStorage y la copia de archivos disponible no aportan cifrado. |
| Imprescindibles para próximas funciones aprobadas | Reusar cámara, micrófono, picker y reproductor Expo para directos, Flashes y cursos. Seleccionar un solo SDK de emisión compatible con New Architecture para captura vertical inicial 9:16 y horizontal opcional 16:9, sin doble emisión inicial. Reusar Expo Notifications para avisos si el binario contiene el módulo. Cuando se apruebe habilitar compras, seleccionar una única integración nativa de facturación que cubra suscripciones premium, restauración y regalos digitales admitidos. |
| Opcionales y aplazables | Biometría local, BLE o SDK de gafas, controles externos de audio, bloqueo de orientación, DRM y descarga protegida, edición avanzada en el dispositivo, mejoras de audio, IA y grabación o emisión dual. Evaluar cada uno solo si hay un requisito concreto, equipo de prueba, soporte Android y mantenimiento compatible. |

- **Flashes y JHighlights.** Reutilizar captura, previsualización y selección. Probar recorte básico y publicación segura con procesamiento de servidor antes de incorporar codificador o editor nativo. Los clips de una grabación autorizada conservan permisos y derechos. Evaluar un editor nativo solo cuando sea imprescindible editar sin red o con requisitos de latencia no alcanzables en servidor.
- **Cursos y Creator Studio.** Reusar `expo-video` y subtítulos cuando el formato lo permita. Catálogo, módulos, progreso, métricas, moderación y derechos pertenecen al cliente JS y al servidor. El acceso a grabaciones premium exige autorización en el origen y CDN. Creator Studio puede aprovechar los módulos de directo, edición y reproducción sin un SDK separado para sus pantallas.
- **Premium y regalos.** El módulo de compras es una dependencia de la primera versión comercial que los habilite. Verificar renovación, cancelación, reembolso, restauración, idempotencia y derechos en servidor. Confirmar reglas de tienda, catálogo, costes y jurisdicción antes de elegir proveedor. La compra, el beneficio, la liquidación y el retiro son operaciones distintas.
- **Compatibilidad.** `package.json` y el lockfile vigentes ya resuelven cámara, notificaciones, reproducción, picker, FileSystem transitivo y Updates. Para cualquier biblioteca nueva, comprobar soporte explícito de Expo SDK 54, React Native 0.81 y New Architecture, y probar integración, permisos y Jelly 2. Una dependencia o permiso nativo cambia el alcance del runtime. Consolidar en una APK solo los módulos ya seleccionados y validados. Después, limitar OTA al runtime compatible y ensayar cambios de servidor y JS desde un canal de prueba.

## Videollamada privada para entrevistas individuales

Un mismo proveedor RTC puede cubrir captura y recepción en los dos flujos con un único SDK nativo. Para directos, usar salas con permisos de publicación y audiencia separados. Evaluar HLS y el reproductor Expo para audiencias grandes, con grabación voluntaria y egress autorizado. Para entrevistas, usar una sala privada con solo dos UUID autorizados por la convocatoria, invitación limitada, tokens cortos por sala y participante, expulsión y revocación al cancelar, y grabación, egress y transcripción desactivados por defecto. La agenda y el estado de la postulación pertenecen a Opportunities. El identificador de una sala jamás concede acceso por sí mismo. Conviene separar proyectos o credenciales para mantener aislados permisos, transmisión y métricas.

| Proveedor a validar | Alcance y costes públicos orientativos |
| --- | --- |
| **LiveKit**, primera opción para una prueba cuando se autorice compilación | El SDK React Native tiene integración Expo mediante plugins y permite salas RTC para ambos flujos. Se puede usar egress separado para HLS/RTMP del directo. Expo Go carece de los módulos nativos. LiveKit Cloud publica Build a US$0 y Ship desde US$50/mes, con consumo de WebRTC, transferencia y egress según plan. Probar expiración, expulsión y posibles reingresos con tokens emitidos justo antes de revocar. |
| **Agora**, alternativa | Un SDK React Native cubre llamada privada, directo interactivo y difusión por configuración de canal. La tarifa de lista publicada es US$3.99 por 1.000 minutos de vídeo HD RTC y US$1.99 por 1.000 minutos HD de audiencia broadcast, más funciones adicionales cuando apliquen. Por ejemplo, 100 entrevistas de 30 minutos con dos participantes suman 6.000 minutos RTC HD, unos US$23.94 a tarifa de lista antes de descuentos y extras. Confirmar compatibilidad Expo SDK 54 y New Architecture con la versión exacta antes de decidir. |

Medir ancho de banda, batería, estabilidad tras reconexión, audio externo, permisos, capacidad de excluir a C de una entrevista y separación de egress. Comparar regiones, tratamiento de datos, grabación, moderación y coste de audiencia. No incorporar dos SDKs por diferencias de interfaz. La selección queda pendiente de una prueba con hardware y presupuesto aprobados.
