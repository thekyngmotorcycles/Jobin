# Piloto de archivos cifrados Android (candidato, no publicado)

Última CI previa: 990051f, run 44990800785, aprobada. El módulo Expo local `modules/jobeen-private-files` implementa AES-GCM con KeyGenerator/AndroidKeyStore, clave de 256 bits no exportada por cuenta, IV generado por proveedor y tag de 128 bits. La referencia/propietario/categoría/tamaño son AAD según el contrato existente. Los archivos se guardan únicamente como ciphertext en noBackupFilesDir; la creación usa staging privado, sync del descriptor y enlace duro sin reemplazo. La apertura no crea una clave nueva si se perdió y no entrega bytes antes de autenticar el tag. No existe borrado genérico, rutas externas ni importación de datos antiguos.

Se conecta al contrato JS con `createAndroidPrivateFileStorage`, pero **no se llama desde las pantallas**. No se ha compilado ni probado el Kotlin en Android. El candidato está limitado a 2 MiB por archivo, al usar TypedArray síncrono de Expo SDK 54 sin base64 ni codificación innecesaria; medir memoria, latencia y disponibilidad de JSI en Jelly 2 antes de ampliar. El contrato lógico general admite 10 MiB, no es la capacidad de este piloto. iOS/web no tienen backend para archivos y no se deposita una copia en claro como sustituto. Las claves del AndroidKeyStore no son necesariamente respaldadas por hardware en todos los dispositivos. El módulo confía en el proceso JS de Jobeen para la autenticación/autorización; no afirma proteger contra código arbitrario dentro del proceso.

## Bloqueos obligatorios
- Confirmar autolinking y configuración de Expo SDK 54 sin iniciar compilación; después solicitar autorización de UNA APK de prueba con runtime/canal/backend aislado. No enviar OTA del módulo ausente a binarios anteriores.
- Revisar el SDK TypedArray (offsets, buffers directos y tipos). Probar todas las llamadas con buffers propios y subarrays, datos conocidos, alteración, sustitución y fallo de Keystore. Verificar errores genéricos, no imprimir claves, propietario ni rutas. Ejecutar en Android real el ensayo de cierre/reinicio durante staging, fallo de espacio, enlace duro no disponible, pérdida de clave y comprobar invariantes; sync del descriptor no garantiza persistencia del directorio ante corte eléctrico.
- Comprobar exclusión de backups, estado antes de desbloqueo del dispositivo, no exposición al explorador de archivos, rendimientos con 2 MiB, no duplicar fotos ni eliminar originales. Los temporales que queden por interrupción son ciphertext; reconciliarlos únicamente mediante inventario de referencias.
- Los bytes descifrados pueden existir en RAM y una vista/decoder puede generar sus propias cachés; integrar fotos y evidencia solo tras elegir y probar un flujo de presentación/subida sin copia persistente en claro. Guardado de referencias requiere propiedad demostrada y proceso de recuperación explícito. No modificar archivos antiguos automáticamente.
- Video grande: no pasar al puente síncrono, ni a SecureStore, ni codificar 500 MB como base64. Preferir respaldo privado autorizado de servidor con transferencia reanudable/streaming y permisos; si se requiere offline, seleccionar cifrado autenticado de streaming revisado con formato y metadatos completos, verificación antes de uso y pruebas de truncación/reordenación. No dividir GCM artesanalmente para simular streaming.

Referencias verificadas del SDK: https://github.com/expo/expo/blob/sdk-54/packages/expo-crypto/android/src/main/java/expo/modules/crypto/CryptoModule.kt y https://github.com/expo/expo/blob/sdk-54/packages/expo-modules-core/android/src/main/java/expo/modules/kotlin/typedarray/TypedArray.kt. No se introduce biblioteca criptográfica de terceros ni dependencia npm nueva; falta comprobar compilación/autolinking cuando esté autorizado.

## Transferencia privada de videos grandes
- Commit 6485dfa aprobó CI 44991151316 (TypeScript y SQL; no compilación Kotlin). Se preparó `private-video-transfer.ts` para una transferencia reanudable TUS de un archivo seleccionado y verificado, con bloques de 6 MiB (requisito documentado de Supabase Storage) y límite total 500 MiB. No lee todo el video en RAM. Candidato no conectado al editor ni a transporte HTTP real.
- Solo bucket privado video-originals, UUID de cuenta y objeto nuevo, MIME permitido, sin upsert y cacheControl 0. El controlador verifica la sesión original antes de leer/enviar y tras cada await, confirma desplazamiento del servidor antes de reintentar, evita simultaneidad y comprueba la identidad/tamaño del objeto mediante contrato de confirmación antes de devolver la referencia para moderación. No guarda URLs, tokens, URI de fuente ni callbacks en disco. Reanudación únicamente dentro de la instancia y sesión originales; un cambio de cuenta o cancelación no puede finalizar el contenido. Una petición ya iniciada puede completar bytes bajo el dueño original; el backend necesita autorización continua y limpieza de cuarentena, no se promete cancelación remota inmediata.
- Tests de simulación: bloques y última fracción, pérdida de respuesta tras escritura, offset inválido, cambio de identidad durante lectura, cancelación, concurrencia y límite. Adaptador futuro: usar TUS revisado según https://supabase.com/docs/guides/storage/uploads/resumable-uploads , host HTTPS directo y autorizado, token exacto por operación, sin redirects/overwrite, caducidad de ticket y HEAD/confirmación del objeto verificadas; no reusar una URL persistida. La fuente deberá ser una copia inmutable o handle verificado del picker, lectura por segmentos con FileSystem SDK 54; no aceptar URI heredadas como evidencia de titularidad. Confirmar que el transporte no retiene varias copias del buffer; examinar RAM y latencia nativas. La API antigua uploadWorkVideo todavía hace arrayBuffer completo y sigue siendo un riesgo pendiente, no declarar resuelto en móvil.
- Videos offline cifrados siguen pendientes de solución de streaming autenticada revisada. La próxima etapa incluye cifrado de metadatos de Flashes/Reels y recuperación explícita de borradores legados; no importar ni borrar datos históricos automáticamente. No activar ni crear APK, OTA o migración alojada sin autorización.
